# Git Quest: HEBUT 科协 AI 部 Git 实验

**实验名称**：Git Quest
**适用对象**：完成「Git 与命令行入门」第一讲的同学
**预计用时**：40–60 分钟
**满分**：10 分

---

## 1. 实验简介

欢迎来到 Git Quest。

本实验由四个 Phase 和一次 Pull Request 组成。四个 Phase 分别藏着一段口令，口令的形式是 `HEBUT{...}`。你需要在**命令行**里把它们一个个找出来，填进自己的成员文件，然后通过 Pull Request 提交给科协 AI 部。

每个 Phase 都不难，但请不要用鼠标在文件夹里乱翻，也不要用编辑器的全局搜索——那样你找得到口令，却学不到任何东西。本实验的真正目的，是当你连上服务器终端的时候，知道该怎么敲命令行。

**评分构成**

| 项目 | 分值 |
| --- | --- |
| Phase 1 | 2 |
| Phase 2 | 2 |
| Phase 3 | 2 |
| Phase 4 | 2 |
| Pull Request 流程 | 2 |

## 3. 获取实验材料

本实验不提供压缩包下载，获取材料本身就是第一道练习。

**第一步，Fork。** 打开本仓库页面，点击右上角的 `Fork`，再点 `Create fork`。完成后你的账号下会多出一个一模一样的仓库，地址形如 `https://github.com/你的用户名/git-quest`。

**第二步，Clone。** 打开终端（Windows 用 PowerShell，macOS 用「终端」），依次敲：

```
cd ~
git clone https://github.com/你的用户名/git-quest.git
cd git-quest
ls
```

能看到 `README.md`、`quest`、`members` 等名字，就说明材料已经在你电脑上了。

**第三步，开一条分支。**

```
git switch -c quest-你的用户名
```

从现在起，你所有的改动都在这条分支上进行。

> **注意**：`git clone` 的地址必须是**你自己 fork 之后**的那个，不是本仓库的原地址。如果你 clone 了原仓库，后面 push 时会因为没有权限而失败。

## 4. 实验任务

### Phase 1：走出迷宫

目录 `quest/phase1/` 下是一串嵌套的文件夹。每一层里有若干个子文件夹，但**只有一个**能继续往下走，其余都是死路——死路的尽头会明确告诉你走错了。

一直走到最深处，那里有一个文件，口令就在里面。

你需要用到的命令只有三条：`cd` 进入文件夹，`ls` 查看当前文件夹里有什么，`cat` 查看文件内容。

> 提示：文件夹名字有点长，敲前几个字母后按 `Tab` 键，终端会帮你补全。

### Phase 2：看不见的文件

进入 `quest/phase2/`，敲 `ls`，你会看到一个 `readme.txt`，打开它，它会告诉你这里什么都没有。

但这个文件夹并不是只有一个文件。有些文件默认是不显示的。

- macOS 的同学：`ls -a`
- Windows 的同学：`ls -Force`

找到那个名字以 `.` 开头的文件后，用 `cat 文件名` 打开它（文件名里的 `.` 也要敲上）。

> 提示：在 macOS 和 Linux 上，文件名以 `.` 开头就表示「隐藏」。这个约定你以后会反复遇到——`.git`、`.gitignore`、`.bashrc`，都是这么来的。
>
> Windows 的同学可能会发现，不加 `-Force` 直接 `ls` 就已经能看到它了。这是因为 Windows 不按文件名判断是否隐藏。没关系，照样 `cat` 打开即可；但请记住这个约定，服务器基本都是 Linux，到时一定用得上。

### Phase 3：大海捞针

目录 `quest/phase3/notes/` 下有 40 个 `.txt` 文件，其中**只有一个**的内容里含有口令。

一个个 `cat` 过去当然也能找到，但有更快的办法：让命令行替你「在文件内容里找字」。macOS 和 Windows 的写法不一样，先 `cd` 到 `quest/phase3`，再按自己的系统敲。

**Windows（PowerShell）**：PowerShell 里没有 `grep` 命令，用它自带的 `Select-String`：

```
Select-String -Pattern "HEBUT{" -Path notes\*
```

`-Pattern` 后面是要找的字，`-Path` 后面是在哪些文件里找，`notes\*` 表示 `notes` 文件夹里的所有文件。

**macOS**：

```
grep -r "HEBUT{" .
```

`grep` 的意思是「在文件内容里找字」，`-r` 表示连同子文件夹一起找，最后那个 `.` 表示「从当前文件夹开始找」。

> 提示：两条命令的输出都会直接显示是哪个文件、哪一行，形如 `notes\note-xx.txt:2:……`。
>
> Windows 的同学也值得记住 `grep`：以后连上的 Linux 服务器上没有 `Select-String`，只有 `grep`。

### Phase 4：翻旧账

前三个 Phase 的口令都躺在某个文件里。第四个不是——**这个仓库现在的任何一个文件里都没有 Phase 4 的口令**。

它在历史里。

git 记录了这个仓库从诞生至今的每一次改动。有一个文件曾经存在过，后来被删掉了，口令就写在它被删之前的内容里。

找到它分三步。以下命令都在 `git-quest` 文件夹（仓库的最外层）里敲。

**第一步：列出历史，找到「删除」的那一次。**

```
git log --oneline
```

这条命令会列出所有的提交记录，每行一个，形如 `a1b2c3d 提交说明`。前面那串字符是这次提交的**编号**。

注意：**最新的提交在最上面，越往下越早。** 通读一遍提交说明，有一条写着「移除」了什么，记下它的编号。

**第二步：看看那次提交删掉了哪个文件。**

```
git show --stat 删除那次的编号
```

输出的最后几行会列出这次被改动的文件，形如 `quest/某某某.txt | 5 -----`，那一串减号表示这些行被删掉了。把这个**完整路径**记下来。

**第三步：回到删除之前，打开那个文件。**

在删除的那次提交里，文件已经不存在了，所以要看它的**上一次**提交。在 `git log --oneline` 的列表里，「上一次」就是删除那一行**正下方**的那一行。用那一行的编号，加上第二步记下的路径：

```
git show 上一次的编号:文件路径
```

举个例子：假如上一次的编号是 `e4f5a6b`，文件路径是 `quest/abc.txt`，就敲：

```
git show e4f5a6b:quest/abc.txt
```

> 这条命令最容易敲错，请对照检查：
> - 编号和路径之间是英文冒号 `:`，前后都**不要**有空格
> - 路径从仓库最外层写起，开头**不要**加 `/`：写 `quest/abc.txt`，不要写 `/quest/abc.txt`
> - 一定要写到具体的文件名，并带上 `.txt` 后缀。如果只写到文件夹（比如 `git show e4f5a6b:quest/`），git 只会列出那个文件夹里有哪些文件，不会显示内容
> - 文件名一个字母都不能错，看不清就从第二步的输出里复制
>
> 小技巧：编号后面加一个 `^` 表示「它的上一次」，所以也可以直接敲 `git show 删除那次的编号^:文件路径`，不用再去找下一行的编号。

## 5. 提交你的答案

### 5.1 填写成员文件

把模板复制一份，改成你自己的 GitHub 用户名：

```
cp members/_template.md members/你的用户名.md
```

> Windows 的 PowerShell 同样支持 `cp`。

用 VS Code 打开它填写（`code members/你的用户名.md`），模板里要填的内容包括：

- 昵称（不要写真名）
- 学号
- 感兴趣的方向
- 一句话自我介绍
- 四个 Phase 的口令
- **每个 Phase 你实际敲了哪条命令**

最后一项是人工审阅时会重点看的部分，请如实填写。写「我用鼠标翻出来的」也比编一条命令强——前者我们会告诉你该怎么敲，后者学不到东西。

### 5.2 提交并推送

```
git add members/你的用户名.md
git commit -m "add 你的用户名"
git push -u origin quest-你的用户名
```

> **第一次 push 时会要求登录 GitHub**，Windows 和 macOS 的方式不一样，具体步骤见第 6 节「第一次 push 时的登录」。

### 5.3 开 Pull Request

push 成功后，打开你 fork 的仓库页面，顶部会出现一个黄色的条，上面有 `Compare & pull request` 按钮，点它。

- 标题写成：`[作业] 你的用户名`
- 正文按模板填写
- 点 `Create pull request`

### 5.4 等待检查与评审

PR 创建后会发生两件事：

**自动检查**。页面下方会出现一个检查项，几十秒后变成绿勾或红叉。点 `Details` 可以看到具体哪一项没通过。它会核对：

1. 你新增的文件名和你的 GitHub 用户名一致
2. 你只改了自己的那一个文件，没有动到别人的（这两项不通过会显示红叉）
3. 模板里的必填项都填了
4. 四个口令分别对了几个

**人工评审**。科协 AI 部的同学会在你的 PR 下留言，可能会请你补充某一处说明。

无论是哪一种，**你都不需要关掉 PR 重开**。直接在本地同一条分支上改，然后：

```
git add .
git commit -m "fix: 改动说明"
git push
```

PR 页面会自动更新，检查也会重新跑一遍。这是本实验最重要的一个认知：**Pull Request 是一个持续的对话，不是一次性的投递。**

检查通过、评审同意后，我们会合并你的 PR。看到紫色的 `Merged` 字样，本实验就完成了。

## 6. 本地自检与常见问题

### 自检脚本

提交前可以先在本地检查口令对了几个：

```
bash scripts/check.sh
```

> Windows 的同学：PowerShell 不认 `bash`。安装 Git 时已经附带了 Git Bash：在开始菜单搜索「Git Bash」打开它，敲 `cd ~/git-quest` 进入仓库，再运行上面这条命令。嫌麻烦也可以跳过，直接提交 PR，由自动检查来告诉你结果。

脚本只存了口令的哈希值，所以读它的源码是拿不到答案的。

### 第一次 push 时的登录

GitHub 早就不支持在命令行里直接用登录密码 push 了。Windows 和 macOS 的同学遇到的情况不一样：

**Windows**：Windows 版 Git 自带一个叫 Git Credential Manager 的登录助手，所以**不需要**自己生成 Token。

1. 第一次 `git push` 时，会弹出一个「Connect to GitHub」的窗口
2. 点 `Sign in with your browser`，浏览器会打开 GitHub 的授权页面
3. 在浏览器里登录 GitHub，点 `Authorize`（授权）
4. 回到终端，push 会自动继续。之后再 push 就不用登录了

> 如果没有弹窗，而是终端里直接要求输入 Username 和 Password，说明你的 Git 没带这个登录助手，请按下面 macOS 的方法生成 Token，在要求输入 Password 时粘贴 Token。

**macOS**：macOS 没有上面那个登录助手，终端会要求你输入用户名和密码。Username 填你的 GitHub 用户名；Password **不是你的 GitHub 登录密码**，而是一串 Personal Access Token（个人访问令牌），生成方法如下：

1. GitHub 网页右上角头像 → `Settings`
2. 左侧最下方 `Developer settings`
3. `Personal access tokens` → `Tokens (classic)` → `Generate new token (classic)`
4. `Note` 随便填，`Expiration` 选 30 天，勾选 **`repo`**
5. 生成后把那串字符复制下来，**它只显示这一次**
6. 终端要求输入 Password 时，粘贴它（终端不会显示任何字符，这是正常的，粘贴完直接回车）

### 其他常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `fatal: not a git repository` | 你不在仓库文件夹里。先 `pwd` 看自己在哪，再 `cd` 进 `git-quest` |
| `Please tell me who you are` | 身份没配好。重新敲课上那两条 `git config --global` |
| 敲完 `git commit` 进了一个退不出来的界面 | 忘了写 `-m`，git 打开了 vim。按 `Esc`，输入 `:q!` 回车，再用 `git commit -m "说明"` 重来 |
| PowerShell 里 `ls -a` 报错 | 那是 macOS 的写法。Windows 用 `ls -Force` |
| PowerShell 里敲 `grep` 提示「无法将“grep”项识别为……」 | PowerShell 没有 `grep`，用 `Select-String`，写法见 Phase 3 |
| `git show` 提示 `path '...' does not exist` | 路径写错了：开头不要加 `/`，要写到具体文件名并带 `.txt` 后缀，或者编号用错了（应该用删除之前那一次的编号）。对照 Phase 4 第三步检查 |
| push 提示 `403` 或没有权限 | 你 clone 的是原仓库而不是自己的 fork。重新 fork 后再 clone |
| push 被拒绝，提示 `rejected` | 远程有你本地没有的提交。先 `git pull`，解决后再 push |
| 自动检查一直显示等待 | 新账号的首次 PR 需要维护者点一下批准。在 Issues 里 at 我们即可 |

## 7. 一点建议

- **卡住超过 10 分钟就去 Issues 提问。** 这不是考试，问问题不扣分。能把问题描述清楚（我想干什么、我敲了什么、它说了什么）本身就是一项重要能力。
- **不要复制粘贴整段命令。** 一个字母一个字母敲，敲错了看报错，这个过程才是你真正在学的东西。
- **善用 `Tab` 和 `↑`。** 熟练的人敲命令时，有一半的按键是 Tab。
- 实验做完如果意犹未尽，可以给这个仓库提一个 Issue 告诉我们哪里写得不清楚——那也是一种贡献。
